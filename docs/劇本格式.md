# 劇本格式（給寫稿的人與 fable）

承峰 2026-11-07：「把需要頻繁對話的程式設計，把劇情獨立出來一個檔案管理」（D224）。
三位熟客的來訪段落與里程碑的演出、日誌、提示，都寫在 `scripts/` 的劇本檔裡；改台詞不用碰程式。
改完請跑 `npm run test:unit`（格式錯了會在這裡擋下來）與 `npm run script:view`（重產 [劇本對照.md](./劇本對照.md)）。

## 一、為什麼選 YAML

| | YAML（選這個） | JSON | 自訂純文字 |
|---|---|---|---|
| 人和 fable 直接讀寫 | 一句一行，像劇本；可以寫註解（`#`） | 引號、逗號、括號多，中文台詞被符號包住；不能寫註解 | 最像劇本，但選項、分支、條件都要自己發明寫法 |
| 選項、分支、條件 | 縮排就是層次，選項底下直接接「選了以後」 | 可以，但巢狀很深時難讀 | 要另外設計語法、另外寫文件 |
| 不能打包（GitHub Pages 直接載） | `vendor/yaml-lite.js`（約 250 行，自己寫的子集，不依賴套件） | 瀏覽器內建 | 要自己寫解析器 |
| 別的工具也讀得懂 | 是（用的是標準 YAML 的子集） | 是 | 否 |

JSON 不用解析器，但每一句都要寫成 `{ "say": "德叔", "text": "……" }`，寫稿時容易漏逗號，也不能在旁邊留審稿的說明，所以不選。
自訂純文字最好寫，但選項、分支、條件、動作都要另外發明，而且只有這個遊戲讀得懂。
YAML 的缺點是縮排要對齊、有些開頭的符號要加引號（見第五節），解析器載入時會指出第幾行。

載入：`src/script.js` 在瀏覽器用 `fetch`（網址帶 `?v=版本號`，換版時不吃舊快取），在 Node（單元測試、`npm run script:view`）直接讀檔；編譯成和原本寫在 JS 裡一模一樣的步驟，由 `main.js` 的 `playStep()` 演出。

## 二、檔案

| 檔案 | 內容 |
|---|---|
| `scripts/_shared.yaml` | 說話者對照、地方、條件的別名、共用的句子（「先坐。」）、**客人註冊表**（名字、第一次來、來店機率、說出名字以前的稱呼、自我介紹） |
| `scripts/yuan.yaml` | 林予安：`segments` 來訪段落 8 段、`milestones` 里程碑 yuan1～yuan6 |
| `scripts/zhe.yaml` | 阿哲：來訪段落 5 段、里程碑 zhe1～zhe6 |
| `scripts/kevin.yaml` | 凱文：來訪段落 7 段、里程碑 kevin1～kevin6 |

不在劇本檔裡的（照舊在程式，規則與排程不能放進劇本）：里程碑的條件、順序、獎勵（`src/story.js`）；段落的窗口、一天的份量、第一杯什麼時候問（`src/visits.js`）；點熟客時的一句話 `TALK`（`story.js`）、熟客最愛的咖啡（`favorites.js`）、告別（`farewell.js`）、打烊後（`afterhours.js`）、店裡的小事（`moments.js`）。這些是字串表或很少改的段落，這次先不搬；之後要搬，照同一套格式加檔即可。

## 三、一段的樣子

```yaml
segments:
  - id: yuan-v2              # 段落 id（存檔記演過哪些，不要改名）
    note: 第 2 次｜點單寒暄    # 給寫稿的人看的說明（遊戲不顯示）
    who: yuan
    kind: visit              # with＝里程碑當天的擴寫、visit＝里程碑之間、reconnect＝離線之後的接回
    after: 1                 # 第 1 個里程碑之後
    before: 2                # 第 2 個里程碑之前（之後就過期跳過）
    steps:
      - look: 予安
      - 旁白: 窗邊的位子，杯子還是溫的。
      - 德叔: 她又坐窗邊了。
      - deshuTo: 予安
      - 德叔: 一樣？
      - 予安: 嗯。一樣。
      - { do: serve, who: 予安, kind: hot }
      - choice: vYuan2Hello   # 選項的 key（存檔記選了哪個，不要改名）
        options:
          - hello: 你好，慢慢坐。          # 選項 id: 選項的字
            then:                          # 選了以後
              - 你: 想坐多久都可以。
          - nod: （點點頭）                # 括號開頭的是動作，老闆不出泡泡
            then:
              - 予安: ……你好。
      - 予安: 窗外那片山，今天的顏色很好看。
        tag: 原句                          # 已上線的句子（沒寫 tag 就是【待定】）
        note: TALK
```

里程碑：

```yaml
milestones:
  yuan1:
    journal:                 # 營業日誌（里程碑在老闆不在時發生）
      - 窗邊來了一位小姐，筆電開著一頁空白的檔案，從開門坐到打烊。
      - text: 她把同一句話刪了三次。
        tag: 劇本
    waiting: ……              # 要老闆在場的里程碑：老闆不在時日誌寫一次「想等老闆在」
    scene:                   # 老闆在店裡時的演出
      - wait: 4
      - 德叔: 窗邊那位小姐，從開門就坐在那裡。
```

## 四、每一種步驟

**台詞**（說話者寫在前面）：`- 德叔: 字`。說話者：德叔、予安、阿哲、凱文、阿公、主管（視訊裡的主管，畫外音）、你（老闆自己說，泡泡在畫面下方）。
台詞底下可以接：`tag:`（`原句`＝已上線的句子、`劇本`＝docs/第一站劇本.md 原文；沒寫＝【待定】）、`note:`（給寫稿的人看）、`name:`（泡泡上的名字改成別的，例如「視訊裡的主管」）。

**旁白**：`- 旁白: 字`。描述場景、動作、氣氛，不是誰說的話。泡泡沒有名字、沒有尾巴，置中斜體、深色底，放在畫面上方中間；鏡頭不會轉（要看哪裡，前面加一步 `look`）。
規則：照片與圖上照舊不寫字；**沖咖啡的步驟用動作演，不用旁白描述**（溫杯、磨豆、注水那些德叔會用動作演出來）；新寫的旁白都是【待定】。

**動作**：

| 寫法 | 意思 |
|---|---|
| `- wait: 3` | 停 3 秒 |
| `- look: 予安`、`- look: 窗外` | 坐著時鏡頭轉向某人或窗外（人物會放大推近，跟對話時一樣） |
| `- glance: 德叔` | 看某人一眼 |
| `- deshuTo: 予安` | 德叔走到某人旁邊 |
| `- deshuHome` | 德叔走回吧台 |
| `- leave: 予安`、`- arrived: 阿公` | 離開、等某人走到位子上 |
| `- music`、`- brewTaste`、`- menu` | 德叔把音樂調小、德叔在吧台試沖、阿哲的豆收進菜單本並問要不要寫上黑板 |
| `- { do: serve, who: 予安, kind: hot }` | 德叔端東西（hot 熱的、iced 冰的、cocoa 可可） |
| `- { do: pose, who: 予安, pose: type }` | 換姿勢（予安：type 打字、napkin 寫紙巾、read 念稿、book 抱書；凱文：closed、free…） |
| `- { do: cat, who: 凱文, lap: true }` | 龍眼走到某人身邊（lap：跳上腿） |
| `- { do: catMove, kind: roll }` | 龍眼在窗台上的小動作（roll、stretch、tail、look；不離開窗台） |
| `- { do: mark, flag: metYuan }` | 記一件事（之後的條件可以用 `flag:metYuan`） |
| `- { do: enter, who: 阿哲, at: bar, pose: muddy, fast: true }` | 走進店裡（at：bar、corner、cornerSide…） |
| `- { do: walk, who: 凱文, at: corner, pose: walk, then: hide }` | 走到某處 |
| `- { do: laugh, who: [阿哲, 阿公] }` | 笑（輕輕跳兩下） |
| `- { do: read, doc: manuscript }` | 打開一張紙（manuscript 予安的稿子、dedication 書的扉頁） |
| `- { do: prop, prop: longanBag }`、`- { do: weather, weather: typhoon }` | 吧台上多一樣東西、天氣變化 |

`{ do: … }` 這種寫法就是程式裡原本的步驟，認得的都可以用；對象（`who`）可以寫中文名字或 id。

**選項**：

```yaml
      - choice: vKevin6Cam        # key：英文，全劇本不能重複；存檔記「選了哪個 id」
        options:
          - meeting: 會議沒關係嗎？   # id 英文小寫開頭（不能是數字），同一組不能重複；字最多 16 個字放得進按鈕
            then:
              - 凱文: ……沒人發現。大概。
          - hill: 看山好。
            then:
              - 凱文: 嗯。以前我都不知道，窗外有山。
```

- 來訪段落裡的選項，選了以後老闆會用「你」的泡泡把那句說出來；括號開頭的（「（點點頭）」）是動作，不出泡泡。里程碑場景裡的選項不說出來。
- **改字可以，改 id 要小心**：存檔記的是 id。改了 id，舊存檔的那個選擇就對不上（分支照沒選過走第一個）。
- 不緊接在選項後面的分支（隔天才用到的選項）：`- branch: key`，底下每個選項 id 接一段步驟。
- 只有一個選項也可以（「讓她坐到打烊吧。」）；沒有 `then` 就是選了以後直接往下。

**條件**：

```yaml
      - when: catSill            # 龍眼此刻在窗台上才演
        steps:
          - 德叔: 龍眼在窗台上翻了個身。
      - when: not met            # 前面加 not 是相反
        steps: …
```

條件一律是字：`catSill`（龍眼在窗台上）、`peeked`（第一天門口那位小姐的小段落演過）、`met`（予安說過名字）、`flag:名字`、`early:名字`、`seg:段落 id`（那一段演過）、`milestone:里程碑 id`（例如 `milestone:yuan2`）。別名在 `_shared.yaml` 的 `conds`。座位、天氣這類條件目前段落裡沒有用到；要加的話，在 `src/visits.js` 的 `condOk()` 加一種，再寫進這張表。
`- ifFire:` 底下的步驟只在開場選了「從今天起，我單方面辭退您」時演（凱文第四幕）。

**第一杯**（段落結尾自然請一杯，`invite`）：

```yaml
    invite:
      drink: black               # 黑板上有這一杯就直接端（any: true＝喝的不限；need: longan＝黑板上要有龍眼乾）
      options:
        - treat: 再一杯黑咖啡？我請。   # 一定要有 treat（我請），另一個選項 id 自己取
          then:
            - 予安: ……好。
        - later: 慢慢寫。
          then:
            - 予安: ……嗯。謝謝你聽。
      missing:                   # 選了 treat、黑板上卻沒有那一杯（德叔只陳述，接著老闆自己選杯）
        - 予安: ……好。
        - 德叔: 黑板上現在沒有黑咖啡。
```

接回段落寫 `invite: yuan-v6`（和那一段同一組）。

## 五、YAML 的小規則

- 縮排用空白（兩格），不能用 Tab；同一層要對齊。
- 台詞裡有半形的「`: `」（冒號加空白）、「` #`」，或台詞開頭是 `- [ ] { } ! & * ' " | > % @` 時，整句用引號包起來：`- 德叔: '例如: 這樣'`。中文的全形標點（：，「」……）都不用。
- `#` 後面是註解，遊戲讀不到；要給寫稿的人看又想留在劇本對照裡的說明，寫 `note:`。
- `yes`、`no` 在這裡是普通的字（不是真假），但選項 id 最好還是用別的英文字。

## 六、改完之後

1. `npm run test:unit`：格式錯了（說話者打錯、對象不認得、選項 id 重複、tag 寫錯、縮排不對）會指出哪個檔、哪一段、第幾步。
2. `npm run script:view`：重產 [劇本對照.md](./劇本對照.md)（每一句的說話者、分支、條件、【待定】）。
3. 段落 id、選項 key、選項 id 是存檔用的，改名前先問；段落要加、要拿掉、窗口要改，是 `src/visits.js` 的事（單元測試裡有段落清單）。
4. 擴寫版（`kind: with`）要包含那個里程碑原場景的每一句台詞與動作，照原本的順序（單元測試檢查子序列）。

## 七、選項存檔的範圍（存檔第 14 版）

`save.story.answers[key] = 選項 id`：劇本檔裡所有 `choice`，加上 `farewell.js` 的啟事（`notice`：`cat`／`slow`／`turnover`）與凱文交接（`kevinBack`：`often`／`regular`）。第 13 版以前的存檔存的是數字，讀檔時照每個 choice 的選項順序換成 id（`save.js` 的 `migrateAnswers()`）。
烘豆、試咖啡、打烊確認、菜單本、請德叔端一杯這些選項是程式直接問、當下用完，不存進 `answers`，不在範圍內。
