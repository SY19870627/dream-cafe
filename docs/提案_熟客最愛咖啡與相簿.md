## 一、現況（已確認）

### 玩家現在能做的事

- 選位子坐、請德叔沖一杯（從黑板上喝的東西選，D185）、佈置與買擺飾、點人搭話、摸龍眼、寫咖啡日記、打烊後的最後一杯、一次客人模式、讀信與營業日誌、打開菜單本決定黑板上寫什麼（佈置的「菜單」、記事本、點黑板，D191）。
- 熟客的故事（予安、阿哲、凱文各 6 個里程碑，`story.js`）是**時間與溫度推著走**的：玩家在場就看，不在場就由日誌回報。玩家沒有辦法「為熟客做什麼」。
- 熟客點什麼是劇情寫死的：予安只點黑咖啡、凱文冰美式（第五幕起點熱的）、阿哲不固定；予安退稿那天德叔端一杯她沒點的熱可可。**和黑板上寫什麼無關**（`menu.js` 開頭的註解）。
- 黑板菜單（D185）讓老闆可以決定寫什麼，但寫上去的東西目前只影響「請德叔沖一杯」給老闆自己的那杯、最後一杯和客人模式，熟客不會因為黑板而有什麼不同（熟客只會在自己的東西第一次寫上黑板時說一句，D187）。
- 現有可以接的線索（都已經在劇本或程式裡，已確認）：
  - 予安：點熟客搭話的句子「再一杯黑咖啡，我就寫得出來。」「阿公以前說，窯火要用龍眼木，煙才會甜。」（`story.js` 的 `TALK`）；第三幕「我想把那個煙寫回來。」；第五幕念的稿子「龍眼要燻三日三夜……」。
  - 阿哲：第一幕送窯烤龍眼乾；第二幕德叔「你阿公曬的豆，我年輕時喝過。」；第四幕阿公喝一口東山豆「這是阮的豆仔」；第五幕德叔「你阿公的是以前，你的是以後。」；第六幕「阿哲的豆」。
  - 凱文：每天下午五點冰美式；第四幕第一次問老闆問題「你當初怎麼敢辭職的？」；第五幕點了一杯熱的；`TALK`「原來下午五點的山，是這個顏色。」；東山的豆的來歷「東山的豆，就是窗外那片山。」（劇本第四幕原文）。
- 菜單本現在有六樣（`menu.js` 的 `ITEMS`）：東山的豆、窯烤龍眼乾、黑咖啡、冰美式、熱可可、阿哲的豆。

### 承峰說的問題

「偏被動、搞不懂自己要幹嘛」：現在玩家能主動做的事，大多是佈置與坐著看；熟客的故事會自己發生，玩家沒有「為某個人做一件事」的目標。這和試玩回饋第一輪的「要等啥沒讓玩家知道」（D179）是同一類問題。

## 二、提案的玩法

### 一句話

**熟客在店裡的時候，老闆可以請德叔端一杯黑板上的東西給他。** 熟客說過的話、劇情裡的小事就是線索；端對了，那一段就完成，留下一張照片收進相簿。端錯了，熟客只說一句溫和的話，什麼都不會少。

### 玩家實際做的事（一步一步）

1. **聽到線索**：熟客在店裡時點他搭話（現在就有），偶爾會說出跟喝的東西有關的一句（新句子，【待定】），例如予安「那天的熱可可，我後來一直想到。」德叔的營業日誌、德叔在吧台的一句話也會帶到（例如「予安小姐今天看了黑板很久。」【待定】）。
2. **打開菜單本，把那杯寫上黑板**：德叔只照黑板沖（D185），所以要端熱可可給予安，熱可可要先在黑板上。這一步把「菜單 A」接進來：菜單本（點黑板就打開，D191）第一次有了「為了某個人」寫上黑板的理由。
3. **請德叔端一杯過去**：點熟客搭話時，如果他今天還沒收過老闆請的那杯，畫面下方的選項多一個「請德叔端一杯給予安」（【待定】）；選了就跳出和「請德叔沖一杯」同樣的選擇（只列黑板上喝的東西，黑板上有點心照舊附一小碟）。德叔照現在的沖煮動作沖、端過去（沿用 `brew()` 與端給熟客的動作，推測可以直接用）。也可以不選，照舊只搭話。
4. **熟客的反應**：
   - **端對了**：熟客說一句（例如予安「……你怎麼知道。」【待定】），德叔在吧台看一眼，畫面淡入那一段的照片（見第四節），停幾秒、可以點掉，照片收進相簿。沒有音效大響、沒有「達成！」字樣。
   - **端錯了**：熟客照樣喝，說一句溫和的話（例如凱文「謝謝。……今天這杯也不錯。」【待定】）。這一天這位熟客就不再收第二杯（一天一杯，避免一直猜），明天再來。
   - **猜了兩次還沒對**：德叔在吧台說一句更靠近的話（例如「她剛才看了窗外很久。像在想那天的雨。」【待定】）。線索永遠是角色的一句話，不是提示框、不是清單。
5. **之後**：那位熟客之後平常來店，桌上的杯子就是他找到的那杯（推測：改 `serveTo()` 的杯子種類就可以），日誌偶爾寫一句。老闆什麼都不做也完全沒關係，故事照常走、溫度照常升。

### 為什麼是「端一杯」而不是讓熟客自己照黑板點

- 照黑板點（菜單提案的選項 B）是熟客自己決定的，玩家還是在旁邊看；「端一杯」是老闆主動為某個人做的一件事，回答了「我要幹嘛」。
- 劇本裡最動人的一杯本來就是「端一杯對方沒點的」：予安退稿那天德叔端的熱可可（第四幕）。這個玩法是讓老闆也能做同樣的事。

## 三、階段怎麼切

### 原則

- 每個階段**跟在一個現有里程碑後面**：那個里程碑發生以後，這一段的線索才會出現、端對了才算。這樣不會和劇情的順序打架，也不會提前爆雷。
- 每位熟客的階段**照順序**（第一段完成，第二段的線索才開始出現），一次只有一個「正在找」的。
- 完成條件只有一個：那一段開放以後，老闆請德叔端「那一杯」給他。
- 每個階段完成都有一張照片；**第三段是那位熟客「最愛的那杯」**。

- **凱文的最愛是「老闆的那杯」**：劇本寫凱文是「和玩家最像的人」，第四幕第一次問老闆問題；他的最愛不是某一支豆子，而是「想知道老闆怎麼過日子」。每個玩家的答案不一樣，猜法是「回想自己喝什麼」，不會和別人重複，也不會被攻略寫死（推測：需要從 `diary`／`closing.bean`／請德叔沖一杯記下最近一杯，現在只有日記與最後一杯有記）。
- **予安第三段要黑咖啡配龍眼乾**：不新增品項，用黑板上已經有的兩樣組合（現在黑板上有點心，每一杯都附一小碟，已確認）。要讓「配不配」成為老闆的選擇，可以在端給熟客時多一個「配一小碟龍眼乾」的選項（推測，見 Q79）。另一個做法是新增品項「龍眼窯特調」（菜單提案選配過、沒做），見方案三。
- 全部九段走完不需要新的溫度門檻；最晚的一段跟在第 3 週的里程碑後面，**第一站結尾前（37°C）就能全部完成**（推測：第六幕都在第 3 週前後，告別要等 37°C）。

### 時間的感覺

- 一天一位熟客最多收一杯，九段最少九次端對；照現在熟客來店的頻率，實際會散在整個第一站（約 3～4 週）。
- 沒有限期：開放之後隨時都可以完成，不會「錯過」；第一站結束以後怎麼辦見 Q80。

### 拿到照片的那一刻

- 端對之後，熟客那句說完、德叔看一眼，畫面慢慢淡成那張照片（全畫面，照片外面一圈白邊與一點點陰影由程式畫），下面一行說明，幾秒後自己淡回店裡，也可以點一下回去。**不跳「獲得照片」的提示框、不出現成就字樣**；第一次拿到照片時，德叔說一句「這張，我收進相簿了。」（【待定】）讓玩家知道相簿在哪。
- 照片是誰拍的（德叔的老相機？只是「回憶」的畫面？）見 Q76。
- 依 D192，照片的動態（淡入、極慢的推近、光影）由程式做，每張只要一張圖。

## 五、相簿

- **從哪裡打開**：
  1. 記事本多一個「相簿」（第一次拿到照片以後才出現，和咖啡日記一樣，沒有就不列入口）。
  2. （建議）吧台上放一本小相簿（程式做的小東西，或之後請畫師畫一張 `prop_album.webp`），點它打開，和點黑板打開菜單本（D191）同一種做法。
- **畫面**：和菜單本、型錄同一種從下面拉起的面板（`openSheet()`），紙張背景沿用 `ui_paper_lined`。分三頁（予安、阿哲、凱文），合照在最後；每張照片是小縮圖（程式在執行時縮，不另外畫縮圖）＋一行說明＋「第 N 天」。點縮圖看大圖。
- **還沒拿到的不顯示**（建議）：和菜單本「看不到還沒解鎖的、不顯示問號格子」（D185）同一個原則，避免變成收集清單。代價是 ACG 的「回想模式」常見的空格（知道還差幾張）沒有了，見 Q77。
- **可以回來看**：照片存在存檔裡，相簿隨時可以打開；第一站結束以後（常態店、之後的站）也可以看。
- **成就**：相簿本身就是成就。不加獎盃、百分比、「完成度 6/9」；三段都找到的熟客，那一頁的最後寫一句他的最愛（例如「予安：黑咖啡，配一小碟龍眼乾。」【待定】）。

## 六、和溫度與任務的關係

- **建議不算溫度**。溫度是 20 個任務算出來的（20°C → 37°C，已確認），第一站的節奏、保底（D55）、徵店長的條件都綁在上面；加進去要重新配每個任務的度數，而且「沒找到最愛就到不了 37°C」會變成必做清單。照片自己就是獎勵。
- **不會和現有任務重複**：20 個任務裡熟客的那 9 個（#5、#6、#9、#11、#12、#15、#16、#18、#20）是「里程碑發生」，玩家不用做任何事；這個玩法的每一段都跟在里程碑**後面**，完成條件是老闆端一杯，兩者不會同時完成、也不會互相卡住。任務 #19「菜單上架『阿哲的豆』」完成後，阿哲第三段才開放，順序剛好接得上。
- **和記事本**：記事本只列已經發生的事（D8），相簿也一樣；不列「還在找的」。
- **和菜單**：不新增「黑板要寫什麼」的規則；只是給老闆「為了某個人寫上黑板」的理由。黑板最多 4 行（D188）照舊，要端熱可可時黑板寫滿了，就照現在的「換掉一行」。
- 如果承峰希望有一點溫度上的回饋，替代做法是：不加度數，只在三段都找到時，德叔在日誌寫一句「店裡暖了一點」（【待定】），見 Q78。

## 七、存檔格式的影響（估計，不實作）

現在是第 7 版（`save.js` 的 `SAVE_VERSION = 7`，已確認）。這個玩法要升到**第 8 版**，新增兩個欄位，舊存檔升級時補空的：

```js
// 8：熟客最愛的咖啡（favorites）與相簿（photos）
favorites: {
  yuan:  { stage: 0, misses: 0, servedDay: 0 }, // stage 完成到第幾段；misses 這一段端錯幾次（給德叔的提示用）；servedDay 哪一天收過老闆請的那杯
  zhe:   { stage: 0, misses: 0, servedDay: 0 },
  kevin: { stage: 0, misses: 0, servedDay: 0 },
},
photos: [], // [{ id: 'yuan-1', day, t }]：拿到的照片（相簿照這個順序）
// 凱文第三段要「老闆最近一次喝的那杯」：
stats: { cups, rainyWindowCups, lastBean: '' }, // lastBean 請德叔沖一杯、最後一杯、客人模式最近一次喝的品項 id
```

- 升級（`migrate()` 的 `v < 8`）：`fill()` 會補上預設值（已確認 `fill()` 用 `defaultSave()` 補缺的欄位）。舊存檔裡已經走得很遠的熟客，從第一段開始找（不自動送照片），已經開放的段落線索會照順序出現；`lastBean` 沒有時用咖啡日記最後一篇的 `bean`，再沒有就是東山的豆。
- 品項 id 用 `menu.js` 的 `ITEMS`；如果採方案三新增「龍眼窯特調」，加一個 `ITEMS` 項目，存檔格式不用再改（`menu.items` 照 D185 的設計可以直接加）。
- 照片的文字、條件放在一個新的純邏輯模組（例如 `src/favorites.js`），照現在 `menu.js`、`moments.js` 的做法用 `node --test` 測。

## 八、美術：照片要畫幾張

依 D192「只用一張圖加程式動態」，**每張照片一張圖**，淡入、推近、光影都由程式做，不畫連續的格子。

| 方案 | 照片 | 張數 |
| --- | --- | --- |
| 方案一 | 每位熟客「最愛」一張 | 3 |
| 方案二（推薦） | 每位熟客三段各一張＋（選配）第一站合照 | 9＋1 選配＝**9～10** |
| 方案三 | 方案二＋德叔 2、龍眼 2、阿公 1＋合照 | 15 |

**規格建議**

- 檔名：`photo_<人>_<段>.webp`（例如 `photo_yuan_1.webp`），合照 `photo_dongshan_all.webp`。
- 橫式 4:3，**2048 × 1536 像素**，不透明 webp（不要壓得太狠）。手機直向時相簿的大圖約 390 CSS 像素寬、三倍螢幕約 1170 像素，2048 寬留得出推近的空間；程式在執行時縮成縮圖與手機尺寸（照現在的規則，畫師**不要自己縮圖或裁切**）。
- 畫風：和店裡同一套手繪（平塗加描線、暖光、3/4 角度）；人物用現有的同一個人（臉、衣服、德叔的錶在左手）。照片的白邊、陰影由程式畫，**圖裡不要畫相框**。
- 每張只要白天或夜裡其中一個（看照片內容），不用兩個版本。
- 優先順序：先畫每個人的第三段（最愛）三張，方案一就能先上線；再補其他段。

## 九、可選的方案

### 方案一：只找最愛（小）

- **內容**：每位熟客一段，第三段那杯就是最愛，前面的線索照第三節的第三段；一位一張照片，共 3 張。相簿只有一頁。
- **優點**：最快、文字最少（約 15 句）、只要 3 張圖；先驗證「端一杯給熟客」好不好玩。
- **缺點**：一位熟客只有一次目標，第 3 週以前都沒得找（最愛都跟在第五、六幕以後），解決不了第一、二週「不知道要幹嘛」的問題。
- **工作量（推估）**：約 1.5～2 天（端一杯的選項與演出、熟客反應、照片畫面、相簿、存檔第 8 版、測試）。

### 方案二：每位三段＋相簿（中，推薦）

- **內容**：第三、四、五節的全部：每位熟客三段、九張照片（＋選配合照）、相簿三頁、德叔的提示、之後熟客桌上換成找到的那杯。
- **優點**：第 2、3 天就有第一段可以找（予安的黑咖啡、阿哲的龍眼乾、凱文的冰美式），剛好接在承峰說的「不知道要幹嘛」最明顯的前幾天；三段的順序本身就是三位熟客的故事（予安：寫不出來 → 退稿 → 阿公的窯；阿哲：被逼來 → 阿公 → 自己的豆；凱文：只會開會 → 看見山 → 想學怎麼生活）；也讓菜單本有了用處。
- **缺點**：文字約 40～50 句（線索、端對、端錯、德叔的提示、日誌、相簿說明），都要審稿；照片 9～10 張；前兩段的答案很明顯（就是他平常點的），對熟悉的玩家可能太簡單（其實是刻意的：第一段是教玩家「可以端一杯」）。
- **工作量（推估）**：約 3～4 天。

### 方案三：方案二＋更多人與帶到下一站（大）

- **內容**：方案二，再加德叔（例如他的琺瑯杯、他年輕時喝過的阿公的豆）、龍眼（牠的「最愛」是老闆的腿上或窗台的陽光，不是喝的）、阿公一段；新增品項「龍眼窯特調」（予安的最愛改成這杯，要德叔試做的演出）；相簿跟著老闆到下一站，熟客的最愛可以寫在下一站的黑板上（企劃「飲品可以帶走」）。
- **優點**：最完整、最像 ACG 的回想相簿；接得上企劃的旅程菜單與第二站。
- **缺點**：德叔那段碰到主線謎題（老先生的身份、琺瑯杯），要很小心不要提前揭露；新品項與試做演出要新台詞；照片 15 張；第二站的設計還沒定。
- **工作量（推估）**：約 1.5～2 週（不含第二站）。

### 比較

| | 方案一 | 方案二（推薦） | 方案三 |
| --- | --- | --- | --- |
| 每位熟客幾段 | 1 | 3 | 3（＋德叔、龍眼、阿公） |
| 第一段最早 | 第 3 週前後 | 第 2～3 天 | 第 2～3 天 |
| 新文字 | 約 15 句 | 約 40～50 句 | 約 80 句以上 |
| 照片 | 3 張 | 9～10 張 | 15 張 |
| 存檔 | 第 8 版 | 第 8 版 | 第 8 版＋菜單新品項 |
| 工作量 | 1.5～2 天 | 3～4 天 | 1.5～2 週 |
| 和「不催促、不跑清單」的風險 | 低 | 低 | 中（項目多、像收集） |

**推薦方案二**：解決「前幾天不知道要幹嘛」最直接，三段剛好是三條故事線的縮影，又不動溫度與劇情。照片可以先畫三張「最愛」，其他六張還沒交之前用程式畫的暫代畫面（或先不給前兩段照片、只有熟客那句話），等圖交齊再補進相簿（推測：照現在「載不到就退回程式繪圖」的做法可以接）。方案三等第二站一起想。

## 十、和調性的對照

| 原則 | 這個提案怎麼做 |
| --- | --- |
| 安靜放鬆、不催促 | 沒有限期、不會錯過；一天一杯，不能一直猜；不做也完全沒關係 |
| 沒有失敗懲罰 | 端錯只是一句溫和的話，熟客照喝、照常來，溫度、基金、劇情都不變 |
| 不跑任務清單 | 不列「還在找的」、相簿不顯示空格、沒有完成度 |
| 不跳提示框 | 線索是熟客與德叔的一句話；拿到照片是畫面淡入、幾秒後淡出，不是「獲得」視窗 |
| 錢不能打破夢想 | 端給熟客的那杯不花錢（咖啡成本只有時間） |
| 沖咖啡用動作呈現 | 端給熟客那杯照現在的沖煮動作 |
