## 二、實作階段

每個階段各自 commit + push，結束前都要：冒煙測試通過、Playwright 390×844 截圖確認、工作目錄乾淨、更新本檔。

### 階段 1：修現有問題、開發者資訊、冒煙測試

測試人員在 390×844 手機與 1280×720 桌機回報的問題，原因分析如下（行號以 commit 31a4b43 為準）。

**a. 沖完後按鈕仍停在灰色「沖咖啡中…」，桌上沒看到杯子**
- 已確認（讀程式）：`brew()` 在倒杯後就把 `state.closeup` 設回 false，提示文字因此恢復（`src/main.js:481-483`）；但 `brewing` 要等德叔端完杯子、走回吧台後才設回 false（`src/main.js:498`、`517`）。這段期間按鈕是 disabled 的「沖咖啡中…」。
- 已確認（計算）：窗邊座的端杯路線單程約 6.8 公尺、走速 0.7 m/s，來回加上停留約 23 秒；這段時間杯子在德叔手上，桌上當然是空的。
- 推測：測試人員是在德叔走路途中看桌面，所以「沒看到杯子」；也可能杯子太小（直徑 8 公分）在 390 寬畫面不明顯。需要實測確認。
- 做法：杯子放上桌就結束 `brewing`、恢復按鈕；德叔走回吧台改成獨立的背景動作（期間再按沖咖啡，就等他回到吧台再開始）。端杯期間按鈕顯示「德叔端過來了」之類的狀態，不要停在「沖咖啡中…」。必要時把杯子放大一點、加一個上桌的小動作（輕微彈跳＋熱氣）。

**b. 喝完一杯後溫度仍是 20.0°C**
- 已確認：`task('first-coffee')` 寫在 `brew()` 的最後（`src/main.js:516`），也就是德叔走回吧台之後；從按下沖咖啡到溫度變化約 50 秒以上。
- 做法：杯子放上桌那一刻就完成任務並升溫；溫度計與右上角數字做一個看得見的上升動畫，並由德叔或龍眼的反應帶出（劇本：「德叔看了一眼溫度計，沒說話」），不跳任務清單。

**c. 390×844 上「角落沙發」標籤與沙發被左緣切掉一半**
- 已確認：俯瞰鏡頭位置固定（`OVER`，`src/main.js:561`），沒有依畫面寬高比調整；沙發在 x = -2.1，直立窄畫面水平視角不夠。
- 做法：俯瞰鏡頭依寬高比調整距離或 FOV，讓整間店（至少三個座位）都在畫面內；標籤投影位置做邊界夾限，不會超出畫面。

**d. 手機點擊目標太小**
- 已確認：座位標籤 `padding: 6px 12px; font-size: 13px`（約 35px 高）、`#speed` `padding: 6px 10px; font-size: 12px`（約 29px 高）。
- 做法：所有可點的按鈕與標籤 `min-height: 44px`、`min-width: 44px`；冒煙測試裡檢查所有可見按鈕的尺寸。

**e. 正常速度沖一杯約 28～31 秒，偏長**
- 已確認：各步驟時間加總（鏡頭 1.6 + 溫杯約 4.4 + 磨豆 5.7 + 悶蒸約 6.1 + 注水 8 + 收壺 2 + 倒杯 1.5）約 29 秒，和回報一致；吧台座之外還要加端杯時間。
- 做法（自行決定，見決定 D3）：六個動作全部保留，縮短停頓與注水時間，正常節奏目標約 18～20 秒；沖煮中「按住畫面」時德叔的動作 ×3，放開恢復，提示文字寫「按住畫面可以讓時間走快一點」。右上角的「正常速度／快轉 ×4」是測試用按鈕，改成只在開發者模式（網址加 `?dev=1`）出現。

**f. 開發者資訊**
- 和作者其他四款遊戲一樣：開發者 SY、GitHub https://github.com/SY19870627 、X https://x.com/nelsonyehfon 。
- 做法：右上角加一個「≡」選單鈕（44px），打開「關於」面板，內含遊戲名稱、開發者 SY、兩個可點連結（`target="_blank" rel="noopener"`）；面板蓋在畫面上、點外面關閉，平常不擋遊戲。之後的設定（重置存檔、下班時間）也放在同一個面板。階段 3 的標題畫面底部再放一行小字。

**g. 輕量冒煙測試**
- `package.json`：`devDependencies` 只有 `playwright`；`npm test` 執行 `node tests/smoke.mjs`。
- `tests/smoke.mjs`：用 Node 內建 `http` 模組在隨機埠開靜態伺服器（不依賴 python），Chromium 以 390×844 載入頁面；檢查沒有 `pageerror` 與 console error、點「窗邊座」能坐下、按沖咖啡後（用測試用的加速參數，例如 `?dev=1&speed=20`）在時限內看到杯子上桌、按鈕恢復、溫度從 20.0°C 變成 20.5°C；檢查可見按鈕都 ≥ 44px；最後存一張截圖到 `tests/output/`（加進 .gitignore）。
- 之後的純邏輯（存檔、離線結算、里程碑判定）寫成不依賴 Three.js 的 ES module，用 `node --test` 測，同樣掛在 `npm test` 底下。
- 遊戲本身不引入建置步驟，GitHub Pages 仍直接吃靜態檔。`node_modules/` 加進 `.gitignore`。
- 注意：本機目前沒有安裝 Playwright 與瀏覽器（已確認），要先 `npm install` 與 `npx playwright install chromium`；README 補上說明。

**h. `.nojekyll`**：Pages 是 legacy（Jekyll）建置，在根目錄加空的 `.nojekyll`，避免 Jekyll 處理檔案。

### 階段 2：存檔、遊戲時間、溫度任務與基金撥款循環

- **存檔**：`localStorage`，單一鍵 `dream-cafe.save`，帶版本號；內容含溫度、已完成任務、基金餘額、倉庫與擺設位置、坐過的座位、熟客來店次數與里程碑、旗標（看過開場、讀過的信）、最後上線時間、玩家設定。存檔邏輯放在獨立的 `src/save.js`，有讀寫失敗（私密模式）時的退路：照常遊戲，只是不存。
- **遊戲時間**：現實一天＝遊戲一天（劇本「節奏設定」）。「開店第 N 天」＝從第一次開店那天起算的本地日曆日數。開發者模式可以「跳到明天」「跳 7 天」來測試。
- **溫度任務**：劇本 20 個任務全部建表（`src/tasks.js`：編號、名稱、類型、溫度、撥款、判定條件）；完成時溫度上升、基金撥款，由德叔或客人一句話告知，不跳任務清單。可以在「關於／設定」面板旁放一本不顯眼的「店的記事本」查看已完成的事（只列已發生的，不列未完成的，避免變成待辦清單）。原型的「第一次調整店裡的擺設」改成劇本的「擺上第一件擺飾」。
- **基金與擺飾**：錢只用來買家具與擺飾，擺放永遠免費。新增倉庫與一個「德叔的型錄」（買東西的介面），價格依劇本：小擺飾 300～800、家具 1,500～5,000、大件約 1 萬。試擺不扣錢，按「確定」才算數，一鍵復原。擺飾清單至少要能達成「擺滿 10 件擺飾」與「第一面書牆」。新擺飾美術先用 `art.js` 的 Canvas 繪製。
- **不做**：錢不夠時不出現「不划算」「餘額不足」等字眼，型錄上只寫「再等等」之類的柔和說法；沒有每日簽到或任務時限。
- **完成標準**：重新整理後所有進度都在；開發者模式跳天數後「開店滿 3 天／7 天」會完成；能買擺飾、放進店裡、溫度與基金數字一致；`node --test` 有存檔與任務判定的單元測試。

### 階段 3：律師信開場、離線營業日誌、第一封老先生的信

- **開場四幕**（劇本「開場」）：第一幕 16:49 辦公室與三選一辭呈結尾（存進存檔，之後凱文里程碑會用到）→ 第二幕律師信 → 第三幕 175 縣道、推門、德叔與龍眼 → 第四幕第一杯教學（先坐、看德叔沖、端上、開啟佈置送三件初始擺飾、溫度 20 → 20.5）。開場只在新存檔時播放，任何一幕都可以「略過」。標題畫面底部放開發者資訊小字。
- **離線營業日誌**：登入時用和上次離開的時間差結算，德叔用手寫風格紙張回報，每天 2～4 條。日誌句子由「每日片段池（劇本範例句）＋可離線的熟客里程碑＋龍眼換位子」組成；「在場」里程碑到期時只寫提示句（例如「凱文先生今天好像有話想說，但想等老闆在」）。離開很多天時只展開最近 3 天，其餘一句帶過，不要一次丟一大疊。
- **第一封老先生的信**：開店第 2 天或溫度 ≥ 22°C 觸發，德叔從抽屜拿出來；信紙畫面（手寫風字體、字有點抖的感覺可用微小旋轉模擬）；讀完鏡頭轉向德叔，他在擦琺瑯杯。
- **完成標準**：新存檔會看到完整開場，舊存檔直接進店並看到日誌；開發者模式跳天數後日誌內容合理；信只出現一次、之後可以在記事本重讀。

### 階段 4：三位熟客故事線與里程碑

- **里程碑引擎**（`src/story.js`，純邏輯可測）：每位熟客的里程碑以條件觸發（開店天數、來店次數、溫度門檻、前一個里程碑、是否在場），不用固定日程。可離線的里程碑在結算時發生並寫進日誌；「在場」里程碑等到玩家在店裡才演出。
- **來店模擬**：每天 3～5 位客人；熟客依自己的習慣時段出現（凱文下午五點、予安整天坐窗邊、阿哲不固定）。玩家在場時，熟客紙片會走進店裡坐下；離線時只累計來店次數。
- **予安**：6 個里程碑＋告別台詞；「寫滿字的紙巾」擺飾、書架上的書。
- **阿哲**：6 個里程碑；「窯烤龍眼乾」食材、颱風夜事件（第 2 週、在場；颱風天的窗外與聲音）、阿公同行、菜單上架「阿哲的豆」。
- **凱文**：6 個里程碑；被罵時德叔把音樂調小、龍眼跳上他的腿；里程碑 4 的三選一回答，若開場選了「單方面辭退」多一句。
- **對話演出**：泡泡只給角色說話；需要選項時在畫面下方出現選項按鈕（≥ 44px）。
- **美術**：新增阿哲、凱文、阿公的紙片（Canvas 繪製，之後換手繪）。
- **完成標準**：開發者模式可以快轉天數走完三條線，每個里程碑都觸發一次、不重複；溫度門檻不會卡住（佈置與體驗任務可當緩衝，見 Q8）；里程碑判定有單元測試。

### 階段 5：店貓龍眼、打烊後模式、一次客人模式

- **龍眼**：依擺飾換睡覺位置（例如有書櫃就睡書櫃旁、有沙發就睡沙發）；任務 #7「第一次跳上你坐的椅子」；可以拒絕互動（點太多次就走開）；日誌會寫牠換到哪裡睡。
- **打烊後模式**（招牌功能）：由玩家按「打烊」開始。客人離開、德叔送上「最後一杯，是老闆的」；燈一盞一盞由玩家自己關；可以整理擺飾、摸龍眼、寫一句「今天的一杯」咖啡日記（存進存檔，記事本可以翻）。沒有任何任務提示。予安念稿（里程碑 5）在打烊後發生。
- **一次客人模式**（任務 #17「以客人身份推門進店」）：鏡頭從門外推門進來、德叔說「歡迎。不急，先坐。」、點單、坐下聽熟客聊這間店（依玩家擺了什麼說不同的話）。第一版只做一次性的事件，觸發時機見決定 D9。
- **完成標準**：打烊流程可以從頭走到尾、日記會保存；客人模式完成後任務 #17 完成；390×844 截圖確認燈光與構圖。

### 階段 6：徵店長與告別、第二封信、第一站結尾

- 溫度達 37°C 觸發，依劇本「徵店長與告別」七個段落，在玩家在場時依序發生，可以分幾天看完：店會自己呼吸了 → 三選一徵才啟事 → 凱文面試 → 予安告別（裱框紙巾）→ 阿哲告別（阿哲的豆、花蓮舞鶴邀請）→ 凱文交接與二選一 → 最後一晚（琺瑯杯、德叔第一次叫玩家的名字）。
- 第二封老先生的信：離開東山的早上。
- 第一站結尾畫面：「你的咖啡地圖」只亮著東山一盞燈，下一站顯示「待續」。結尾後仍可以回東山當客人坐坐（店轉為常態經營，凱文顧店）。
- **完成標準**：開發者模式從 36.5°C 開始能完整走完告別；結尾後重新整理仍能進入常態店。
