# 提案：ACG 式立繪長對話

> 承峰 2026-11-07 原話：「另外我還是要加強文本，你目前每天都簡單一兩句話，我希望類似ACG遊戲，有立繪跑出來的長對話」
>
> **狀態：只是提案。** 沒有改程式、測試、資產、其他文件，也沒有增加遊戲版本（不是遊戲改動）。依本機 main `cf950c9`（v0.1.2）只讀。
> 本文件**新寫的台詞一律逐句標【待定】**；引用劇本原文與已上線台詞**一字不改**，並標出處。所有「建議」都要等承峰決定（第六節），不算定案。
> 「已確認」＝讀過程式或文件；「推測」＝還沒實測，實作時要用 Playwright 在 390×844 量過。

## 零、一頁摘要

1. **形式**：劇情場景（四句以上）改成「立繪從畫面左右滑入＋底部文字框＋姓名牌」，**點一下前進**，有「自動」「回顧」「略過」三個鈕；3D 店內畫面留在後面變暗、鏡頭照舊轉向說話的人。店裡的零碎小事（搭話、小事件、擺飾反應、沖煮時的一句）**繼續用泡泡**，兩種分得清楚：泡泡是店裡的聲音，立繪是故事。
2. **份量**：每天最多 **1 場長場景（13～25 句）＋2 場短場景（4～12 句）**，四個觸發點是開店、熟客到訪、回憶照片之後、打烊。有劇情的晚上約 30～50 句，安靜的晚上 10～20 句；每場只演一次，錯過不補、不計數、不催促。
3. **不打斷**：只在「沒有面板、沒在沖煮／佈置／試咖啡／烘豆、沒有別的演出」時開始；熟客的長場景建議先在他頭上出現「…」標記，老闆坐下或點他才開始。
4. **範例**：予安第三幕「說出龍眼窯」的長版，23 句（3 句是既有台詞、20 句新寫【待定】），一個不影響結果的選項。
5. **美術**：新畫「半身立繪」，一個表情一張圖、圖上不寫字、沿用現有畫風和服裝；共 **27 張（另 1 張選配）**；第一批是範例用的 **9 張**，其中 2 張可先用現有圖暫代，非畫不可的是 **7 張**。沒交圖前可以先把現有全身圖裁成半身暫代（推測畫質勉強可用，要實測）。
6. **要承峰決定**：第六節 14 題，每題附建議。

### 3. 立繪的動作（全部程式做，一個表情一張圖，符合 D192）

| 動作 | 做法（建議） |
| --- | --- |
| 滑入 | 從同側畫面外 60px 滑到定位，同時透明度 0→1、往上 8px，0.28 秒 ease-out |
| 滑出 | 反過來，0.22 秒 |
| 換表情 | 同一位置交叉淡入 0.16 秒，不滑動 |
| 換人說話 | 不滑動；亮度、大小、前後順序 0.15 秒過渡 |
| 呼吸 | 說話中的那張每 4 秒上下縮放 1.5%（和現有紙片的呼吸一樣是程式動態） |
| 笑（`laugh`） | 輕輕跳兩下（沿用現有 `laugh` 的感覺） |
| 減少動態 | 系統設定 `prefers-reduced-motion` 時只淡入淡出，不滑、不呼吸 |

### 4. 點擊前進、自動、略過、回顧

- **點擊前進**：文字逐字出現（每字 35 毫秒，約一秒 28 字）。**打字中點一下＝整句直接出現；整句出現後點一下＝下一句。** 畫面上除了三個功能鈕、選項以外，點哪裡都算（包括立繪和 3D 畫面）。連點保護：上一下之後 0.25 秒內不收第二下，避免一次跳兩句。
- **自動**：按一次切換。開的時候，整句出現後照現在的公式等（`min(6500, 1900 + 字數 × 115)` 毫秒），所以和現在的節奏一樣；鈕上有亮點表示開著。記住玩家的選擇（存在設定，不是存檔進度）。
- **略過**（建議，決策 A5）：第一下鈕變成「再按一次略過」2 秒，第二下才略過（和誤按打烊 D205 同一種保護，不跳確認視窗）。略過＝**跳到這一場的結尾**：
  - 場景帶來的事照樣發生（里程碑記進存檔、溫度任務、擺飾收進倉庫、品項收進菜單本），**不因為略過而少拿或多拿**。
  - **選項不略過**：遇到選項就停下來讓玩家選（選項會存檔，例如凱文第四幕 `kevinQuit`、告別的兩句話）。
  - 打開紙張（予安的稿子、扉頁）、照片淡入這種「要看的東西」也停下來。
  - 被略過的句子照樣寫進回顧。
- **回顧（log）**：按「回顧」打開全畫面面板（沿用記事本的紙張樣式與 `#sheet` 的面板），由上到下是今天看過的對話，最新的在最下面、打開時自動捲到底；每句一行：小字姓名＋台詞；玩家的選擇寫成「你選了：……」；不同場景之間空一行並標「開店／予安／打烊」這類小標。底部「回到對話」鈕 44px。**回顧裡不重播聲音、不顯示立繪**（只是讀）。
  - 範圍（建議，決策 A6）：對話中的「回顧」只看今天；記事本多一頁「這幾天的話」，按天保留最近 7 個開店日（不計數、不標「還有幾段沒看」）。
- **讀不完怎麼辦**：「≡」選單、切到別的 App、手機鎖螢幕，都只是暫停；回來時接著同一句。重新整理頁面時，**那一場從頭再演一次**（存檔只記「演完了沒」，推測這樣最單純）。

### 6. 動作照舊用 3D 演，不用文字描述

AGENTS 定案：「沖咖啡要用動作呈現……對話泡泡只用在角色說話，不要拿泡泡描述備餐步驟」。所以對話模式**不加旁白字**（沒有「（德叔遞上毛巾。）」這種句子）。遇到 `serve`、`deshuTo`、`cat`、`music`、`weather`、`walk`、`enter`、`leave`、`brewTaste` 這些步驟時：

1. 文字框與立繪一起淡出（0.2 秒），暗幕退到 15%；
2. 3D 畫面照現在的方式演完那個動作（鏡頭也照舊）；
3. 淡回對話模式，接下一句。

`read`（稿子、扉頁）與照片淡入：對話模式整個收起，照現有的畫面顯示，關掉後回來。

## 三、節奏：每天幾場、每場多長、什麼時候開始

### 1. 四種觸發

| 類型 | 長度 | 誰 | 什麼時候開始 | 一天上限 | 錯過 |
| --- | --- | --- | --- | --- | --- |
| **開店小景** | 短，4～8 句 | 德叔＋老闆（有時加上已經在店裡的熟客） | 進店、店裡的燈亮之後，**第一次坐下之前**（取代那天「燈亮了。老闆，今天想坐哪裡？」那一句泡泡）。**只有「有理由」的日子才有**：第一次下雨、颱風過後的隔天、讀完信的隔天、新的大件擺飾、開店滿 7／14 天、隔了 3 天以上才回來；其他日子照舊那一句泡泡 | 1 | 不補；理由過了就沒了 |
| **熟客到訪** | 長版里程碑 13～25 句；里程碑之間的小段落 6～12 句 | 熟客＋德叔（＋老闆的選項） | 熟客走進來、坐定之後；畫面安靜（第 3 點）時，熟客頭上出現「…」標記，**老闆坐下或點他才開始**（建議，決策 A2） | 長場景 1；小段落 1 | 里程碑照現有規則等老闆在（日誌寫「想等老闆在」）；小段落錯過不補 |
| **回憶解鎖之後** | 短，4～8 句（照片後記） | 那位熟客＋德叔 | **不在照片淡入當下演**：照片＋已定的那一句（「煙是甜的。」、「阿哲的豆。……黑板上，是我的名字。」，D202、D203）保持原樣；後記在**下一次**那位熟客到店時演 | 1 | 不補 |

### 3. 不打斷的條件（建議）

對話模式只在**全部成立**時才開始：

- 沒有面板開著（記事本、型錄、倉庫、菜單本、便條、測試紀錄、試咖啡調參數 `#tune`、日誌、信、照片）；
- 不在佈置模式、不在選項中；
- 德叔沒在沖煮、沒在烘豆、沒在演店裡的小事（`moments.busy`）；
- 鏡頭沒在移動（現有的 `camSettled()`）；
- 熟客的長場景：老闆坐著（現有的 `needSeat` 已經是這個想法）。老闆在俯瞰時，熟客頭上只出現「…」標記（44px，可以點），**不自己開始**；標記一直留到那天打烊，不閃、不跳提示框。

開始以後，**新的事情排隊**：別的熟客走進來就先坐好、不打招呼；店裡的小事、德叔的提醒（便條、測試紀錄）等對話結束、安靜一陣子後才輪到（沿用現有「店裡的小事」的佇列）。

### 4. 真實日期

遊戲照舊是「現實一天＝遊戲一天」、營業從老闆設定的下班時間開始（`docs/第一站劇本.md:223`；`src/clock.js`）。對話模式要配合的地方：

| 情況 | 建議 |
| --- | --- |
| 凱文下午五點才來（`KEVIN_HOUR`） | 不動；凱文的長場景本來就在五點以後 |
| 很晚才進店（例如 23 點以後） | 長場景照樣可以開始，但只出「…」標記、不催；打烊對話縮到最多 4 句 |
| 好幾天沒來 | 營業日誌照舊結算（短句，不改成立繪）；回來那天**只演一場**最該演的（下一個等老闆在的里程碑），其他小段落不補、不堆積 |
| 對話演到一半過了午夜 | 那一場算在**開始那天**演完，再換天（推測，現有換天的時機要實測） |
| 週末白天進店 | 不特別處理；熟客照現有的排程 |
| 節日（中秋、冬至、過年） | 建議**先不做**（決策 A11）：做了就很像「限時活動」，錯過的人會覺得少了什麼；如果要做，只能是開店小景的一兩句、不給任何東西、錯過不補 |

### 5. 避免每天重複

- **每一場只演一次**（存檔記演過的 id，和 `moments` 記前三天小段落的做法一樣）。重看只能從回顧讀字（決策 A7 是否要「重播」）。
- 開店小景要「有理由」才有，所以不會天天出現；打烊的話題庫抽過就不再抽，用完回到現在的固定 4 句（`src/afterhours.js` 的 `CLOSING`），**不會循環播同一段**。
- 句子依天氣、季節、熟客進度挑，不依「連續幾天來」挑（沒有簽到感）。
- 寫稿規則：
  - 一句 ≤ 40 字；德叔的句子盡量 ≤ 15 字（他「短句、不說教」，`docs/第一站劇本.md:17`），長場景主要由熟客說，**德叔的句數不超過全場的三分之一**；
  - 不寫旁白、不寫備餐步驟；
  - 已定的台詞放進長版時一字不改，前後只加不改；
  - 每場寫之前先列「這一場還不能說的事」（第四節的表就是例子）；
  - 不出現「KPI」「不划算」這類字（文字校對的單元測試會擋）。

## 五、給畫師的表情立繪清單

### 1. 共通規則（建議）

- **一個表情一張圖**，表情之間由程式交叉淡入；不交臉部差分、不交要逐像素對齊交替的圖（D192：「只用一張圖加程式動態」）。
- **圖上不寫字**（D202）：不畫對話框、不畫擬聲字、不畫漫畫符號（汗滴、青筋、愛心、問號這類，決策 A12）；筆電、書、紙袋上不要有字或標誌。
- **沿用現有畫風與人設**：柔和的日系手繪、淡暖色、乾淨線條、3/4 角度（現有 `char_*_stand` 的畫法）；服裝、髮型、配件和現有圖一樣——德叔白襯衫＋深咖啡背心、袖口捲兩折、左手老錶、灰白頭髮梳整齊；予安長黑髮、灰藍毛衣、卡其長裙；阿哲黃色棒球帽、橄欖綠襯衫外套、白 T；凱文黑框眼鏡、淡藍襯衫、黑色耳罩式耳機掛脖子；阿公斗笠、米色短袖襯衫、拐杖。
- **構圖**：半身（頭頂到大腿中段），身體朝畫面中央微側（左位的人朝右、右位的人朝左，第二節第 2 點），**程式不鏡像**。手放鬆、**不拿東西**（才能跨場景用），只有寫明的那張才拿。
- **規格**：畫布 **1400 × 2048 像素**，透明背景 webp；頭頂離上緣約 120 像素；**同一個角色所有表情的眼睛高度一致（差 ±8 像素以內）、肩寬一致**，交叉淡入時才不會跳；下緣切在大腿中段，不用畫腳。不加陰影、不加背景光暈。
- 檔名：`portrait_<人>_<表情>.webp`，放 `assets/art/`。原圖不改不壓（AGENTS）；程式執行時縮放（**不要套用人物紙片的「手機縮成 1024 高」**，立繪在 390 寬手機上顯示 470px 高，Retina 約需 1400 像素高，推測縮到 1536 高剛好）。

## 七、不改的事、風險與之後實作的大小（推測）

**不改的事**

- 里程碑的條件、順序、D53 的每天上限、溫度任務與撥款、熟客最愛三段、照片與已定的那一句（D202、D203）、營業日誌（照舊是德叔手寫的短句）。
- 已定的台詞與劇本原文一字不改；新句子只加在前後。
- 龍眼固定睡窗台（Q64、D170），對話模式不把他搬下來；老先生不出現；德叔的秘密、老先生的身份、凱文接任店長不提前。
- 錢、溫度不因為看不看對話而變；沒有「還有幾段沒看」的數字。

**風險**

- **文字量與審稿**：9 場「在場」里程碑長版約 180 句、加上中版與小段落，第一站可能多 400～600 句；照現有建議一批不超過 60 句送審（Q131），審稿是最大的工。
- **德叔變多話**：長場景容易讓德叔說太多、說教。寫稿規則限制他的句數與字數（第三節第 5 點）。
- **手機效能**：暗幕＋兩張大圖＋3D 場景同時跑；不做模糊，立繪縮到 1536 高，推測沒問題，要在低階手機實測。
- **和泡泡的分界**：兩種同時出現會亂；對話模式開著時泡泡一律不出。
- **暫代圖的觀感**：裁切的全身圖手上拿東西（筆電、紙袋），只能撐到第一批交圖。

**之後實作的大小（推測，本次不做）**

- 介面：`index.html` 加對話層（立繪兩格、文字框、姓名牌、三個鈕、回顧面板）；`main.js` 的 `playSteps()` 遇到 `say` 時改走對話層、動作步驟前後淡出淡入；約 2～3 輪。
- 資料：`say` 步驟多一個表情欄位（例如 `face: 'shy'`），長版場景放在原本的模組（`story.js` 等），自行補寫的照舊標 `// 【待定】` 並跑 `npm run pending`。
- 存檔：記「演過哪些場景」與最近 7 天的回顧；要升存檔版本並寫 `migrate()`。
- 美術：`art.js` 加立繪的載入與「退回最接近的表情」。
- 測試：純邏輯（今天能演哪一場、上限、略過時效果照給）用 `node --test`；Playwright 在 390×844 截圖（對話中、選項、回顧、略過）；冒煙測試要多一段（單跑約 16 分鐘，注意別和其他 agent 同時跑）。
- 這些都是推測，要承峰定了第六節再排。
